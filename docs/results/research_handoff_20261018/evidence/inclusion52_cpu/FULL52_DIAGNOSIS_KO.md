# Full-data inclusion52 CPU 최종 진단

결론: Full-data의 낮은 inclusion AP를 단순한 작은 결함 미검출만으로 설명할 수 없다. 낮은 저장 임계값에서52개 중42개는 정답 클래스 IoU≥0.5로 일대일 매칭되고, 나머지10개는 같은 클래스의 위치 오류다. 작은 높이 구간에8/10 위치 오류가 집중되지만, 중간·큰 구간에도 저신뢰도의 정답 후보가 많다. 이 단계로 원인 진단을 종료하고 고정 Full-data best.pt의1024 추론 해상도 민감도 실험 한 번을 다음 실험으로 추천한다. 이번에는 실행하지 않았다.

## 1. 비교 범위와 재사용

- 완료 Full1604·YOLO26s·SGD100·640의 저장 JSON만 읽었다. 독립 Test는 읽지 않았다.
- inclusion30이미지·52 GT만 매칭했다. 같은52개의 R5 DINO 오류표를 그대로 재사용했고 R5를 다시 추론하거나 매칭하지 않았다.
- 기존 analyze.py의 ious/sizebin 함수를 읽기 전용 import했다. main은 호출하지 않았다. 같은 prediction confidence 내림차순·JSON row 동점, 같은 최대IoU·GTindex 동점, 같은A→B→C→D 순서다.
- 모든 클래스 예측은52개 GT와의 다른 클래스 중첩 판단에만 사용했다. 전역 inclusion 예측/비매칭 건수는 기존 임계값 집계와 연결하기 위해 세었다. 다른 클래스 GT를 새로 분석하지 않았다.

## 2. 기존 네 유형을 그대로 비교

| 모델 | conf≥ | 정답 A | 다른 클래스 중첩 B | 위치 오류 C | 미검출·기타 D |
|---|---:|---:|---:|---:|---:|
| DINO | 0.001 | 33 | 1 | 14 | 4 |
| DINO | 0.25 | 7 | 5 | 2 | 38 |
| Full1604 | 0.001 | 42 | 0 | 10 | 0 |
| Full1604 | 0.25 | 16 | 3 | 8 | 25 |

정상은 같은 클래스의 일대일 IoU≥0.5 매칭이다. B는 A가 없는 GT에 다른 클래스 IoU≥0.5가 있는 경우, C는 A/B가 없고 같은 클래스 최대IoU가0.1 이상0.5 미만인 경우다. D는 그 외이며 모델 내부에서 아무것도 인식하지 않았다는 뜻이 아니다.

Full의 conf.25 정답16·비매칭 inclusion 예측44가 이미 저장된 합계와 정확히 일치했다. 기본conf.001에서 B/D가0이라는 것은 모든 GT에 적어도 같은 클래스의 IoU≥.1 후보가 존재했다는 뜻이다. IoU.5에서의 완전 검출이나 의미적 클래스 혼동 부재의 증거는 아니다.

## 3. 저신뢰도를 분리한 다섯 범주

conf.001의 기존 네 유형 중 A를 해당 매칭 score≥.25와 .001≤score<.25로만 나누었다. 나머지 B/C/D는 conf.001 기준을 그대로 유지했다. 다섯 열은 상호 배타적이며 합계52다. 이 표를 conf.25에서 다시 정해진B/C/D와 섞지 않는다.

|---|---|---:|---:|---:|---:|---:|---:|

높이 구간은 기존 nominal_height640<16 /16–<32 /≥32를 그대로 사용했다. 원본/640 환산 너비·높이·면적·짧은변과 loader_height640는 객체별 CSV에 함께 보존했다. 높이≥32를 면적이나 짧은변 기준의 큰 객체라고 바꾸어 해석하지 않는다.

## 4. 해석

1. 데이터 증가가 도움이 없었던 것은 아니다. 낮은 임계값 정답은 R5 33→Full42개다. 높이≥32에서는13→21/22개로 증가했고, 중간은13→14/15개, 작은 구간은7→7/15개였다. 큰 구간의 피복은 개선됐으나 작은 구간의 IoU.5 정상 수는 늘지 않았다.
2. Full의 위치 오류10개 중8개가 작은 높이 구간이다. 중간/큰 구간에는 각각1개다. 같은 정답으로 크기를 고정한 기술통계이며 서로 다른 이미지·객체·종횡비·대비의 인과 통제가 아니다.
3. Full의 정답42개 중26개는 낮은score로 conf.25에서 탈락한다. 그26개는 작은3, 중간9, 큰14개다. 저신뢰도는 소형 객체에만 집중되지 않는다. confidence가 낮다는 사실만으로 calibration 오류나 분류 손실 부족을 확정하지 않는다.
4. Full 정답 매칭42개의 IoU 중앙값은0.6080, score 중앙값은0.20974다. 기존 IoU.5 매칭 중 .75 이상은9개뿐이다. R5는33개 중6개다. 대상 구성도 달라졌으므로 중앙값 차이만으로 Full의 위치 성능이 악화됐다고 단정하지 않는다. 이9개/6개는 .75에서 재매칭한 AP75가 아니다.
5. Full inclusion AP50=18.3948%, AP75=1.7976%, AP50-95=5.7491%는 기존 결과를 인용했다. conf.25에서 TP16·비매칭44, conf.001에서 TP42·비매칭2088의 예측이 존재한다. 높은 recall 후보가 있어도 오탐·신뢰도 순위·엄격IoU 성능이 남는 양상이며, 이 건수로 AP5.75를 수학적으로 원인 분해한 것은 아니다.
6. 대표 다른 클래스 오류는 conf.001에서0개지만 정상과 공존하는 타 클래스 중첩은 있을 수 있고 conf.25에서는3개가 된다. 임계값 변경 후 대표 유형이 바뀐 것이며 특정 클래스가 inclusion 예측을 억제했다고 단정하지 않는다.

## 6. 결론과 종료

직접 확인한 병목의 양상은 작은 inclusion의 부정확한 위치와, 크기에 관계없이 낮은 신뢰도·많은 비매칭 예측의 공존이다. 입력 축소가 주원인인지, 분류/회귀 학습·GT 경계·대비 중 무엇이 원인인지는 저장 결과만으로 확정하지 않는다.

다음 한 번은 고정 Full-data 모델의1024 추론으로 해상도 변경에 실제로 민감한지 시험한다. 추가 손실 가중치·크롭 학습·샘플링을 동시에 바꾸지 않는다. 상세 고정 조건·성공/기각 해석은 NEXT_EXPERIMENT_KO.md에 기록했다. 이번 분석 이후 추가 원인 분석을 자동으로 반복하지 않으며 실제 개선 실험도 아직 실행하지 않았다.

CPU 실제 연결 계산 0.114초, IoU 관계 2781개. GPU/CUDA·모델 가중치 접근·새 추론·학습 없음. 입력 SHA 작업 전후 일치. 이는 전체 사람이 보고서를 작성한 시간이 아닌 CPU 계산 구간 실측이다.
