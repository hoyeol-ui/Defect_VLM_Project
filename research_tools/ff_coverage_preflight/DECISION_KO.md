# Global–Local 선택 진단: 진행 여부 검토안

2026-10-16 · 실행 전 검토용 단일 문서

**권고: 새 방법을 확정하지 말고, 기존 CLS cache만 사용하는 교체 가능성 진단부터 검토한다.** 이번1대1 교체안에서는 그 단계가 통과해야 Patch 추출·사용을 검토할 이유가 생긴다. 2026-10-16 보완: 집에서 사용할 FF 재현·최초 1대1 교체 진단 코드를 별도 준비한다. 실제 원본을 이용한 실행·새 선택·특징 추출·GPU·학습·평가는 아직 하지 않았다.

## 1. 이번에 답할 질문과 답하지 못하는 것

> 기존 FF의 CLS coverage를 유지하면서 Patch 정보를 반영하면, 단순 ID 변경을 넘어 국소적인 차이가 있는 이미지로 선택이 달라지는가?

이 질문에는 세 단계가 있다.

| 단계 | 확인할 내용 | 그 결과만으로 주장할 수 없는 것 |
|---|---|---|
| 교체 가능성 | 같은 예산·반경에서 허용되는 이미지 교체가 있는가? | Patch가 유용하다 |
| 선택의 차이 | 중복 이미지 치환을 넘어 국소 시각 정보가 달라지는가? | 실제 결함 정보가 늘었다 |
| 결함 관련성 | 차이가 결함 형태와 관련돼 보이는가, 배경·조명인가? | YOLO AP 개선·학술적 신규성 |

이번 다음 단계는 **앞의 두 단계와 제한된 시각적 점검**까지다. YOLO 학습, AP/nAULC 평가, 탐지기·학습 조건 변경, K8 학습은 포함하지 않는다. 이미 라벨된 R4의 고정 표본에서 box 겹침을 보는 탐색적 사후 진단을 포함한다. 미라벨 정답을 여는 독립 정량 검증과 탐지 효용 평가는 별도로 결정한다.

## 2. 기존 설계를 숙고한 결과

### 유지할 점

CLS FF를 기준 집합으로 두고, 미라벨 GT 없이 Patch 신호를 계산하며, 반경을 악화시키는 교체를 허용하지 않는 접근은 진단 질문에 맞는다. 교체가 없으면 FF를 그대로 반환하는 것도 정당한 결과다. 다만 다음 다섯 가지를 명확히 해야 한다.

1. **반경 유지와 대표성 전체 유지는 다르다.** 최대 최근접 거리만 같아도 평균·95분위 거리나 중복성은 악화될 수 있다. 이번에 보장하려는 것은 지정한 CLS 최대 반경이며, 나머지 지표도 함께 보고해야 한다.
2. **현재32×32 shortlist에서 교체가 없다고 가능한 교체가 없다고 할 수 없다.** 후보 제한 때문에 놓친 것인지 먼저 구분해야 한다.
3. **최대10 pass는 최대10번의 교체만 허용한다.** 선택 변화가 작다는 결론이 탐색 상한 때문일 수 있다. 최종 교체 이미지 수도 반복 교체 때문에 더 적을 수 있다.
4. **Patch 목적함수 상승은 독립적인 효용 증거가 아니다.** 이를 최대화했으므로 상승 자체는 예상되는 결과다. 임의의 허용 교체보다 나은지와 실제 영상 차이를 확인해야 한다.
5. **이미 라벨된 집합이 크면 local coverage가 포화될 수 있다.** 목적함수에 개선 여지가 없는 경우를 Patch 자체가 무용한 경우와 구분해야 한다. 4×4 평균은 작은 결함을 희석하고, prototype의 max 집계는 공간 배치를 버린다.

따라서 아직 확인된 것은 설계의 필요성이지, 좋은 선택 방법의 존재가 아니다. prototype·coverage·교체의 조합을 만들었다는 사실만으로 신규성을 주장하지 않는다.

## 3. 첫 진단의 범위를 고정한다

**제안 범위: GC10-DET 하나, 획득seed2026091901 하나, 기존 FF의 R4→R5 한 번.** K8의 global trade-off 사례가 있는 데이터셋으로 좁히는 사전 선택이다. 결과를 보고 유리한 데이터셋·seed로 바꾸지 않으며 NEU나5개 seed 전체에 일반화하지 않는다.

| 항목 | 고정할 값·의미 |
|---|---|
| 평가 대상 특징 pool V | 기존 GC10 train pool1604장. dev/test 제외 |
| 고정 라벨 집합 L | 원래 FF R4의481장. 제거·교체 금지 |
| 기준 신규 집합 B | 원래 FF R5에서 R4를 뺀80장 |
| 기준 전체 집합 T₀ | L∪B, 총561장 |
| 변경 가능 범위 | 80장 신규분만 교체. R4까지의 선택 이력 보존 |
| 특징·거리 | 기존 F518 CLS384차원, 기존 정규화·거리·tie 규칙 유지 |
| coverage 기준 | `ρ(T)=max_{x∈V} min_{y∈T} [1−g(x)ᵀg(y)]`, `ρ(T)≤ρ(T₀)` |
| 탐지기·학습seed | 이번 진단에서는 학습하지 않으므로 해당 없음 |

이렇게 좁히면 **같은 L에서의 reference가 실제 원래 FF R5와 일치**해야 한다. 기존 설계의 여러 라운드에 걸친 경로 차이 문제를 피할 수 있다. 다만 마지막80장의 보완 가능성만 검증하며 전체 능동학습 경로의 개선은 검증하지 않는다.

집에서 정식 cache·행 ID·입력 순서·R4/R5 목록·원래 선택 순서·hash와 실제 실행 소스를 연결한다. 거리의 dtype·연산 방식·동점 처리·즉시 갱신 규칙을 확인하고, 원래 FF의 마지막80장과 재계산 결과의 집합 및 획득 순서가 정확히 일치하는지 최우선으로 검사한다. 원래 순서 기록이 없다면 임의 정렬로 대체하지 않고 원본 실행 근거부터 복원한다. 재현되지 않으면 Patch로 넘어가지 않는다. K8 원본은 배경 근거 확인에 유용하지만 이번 진단의 선택 입력이나 필수 baseline은 아니다.

## 4. 최소 실행 계획 — 승인 후 순서

### 1단계: CLS만으로 교체의 여지가 있는지 확인

Patch 추출 없이, `v∈B` 한 장을 빼고 `u∈V\T₀` 한 장을 넣었을 때 반경을 유지하는지 검사한다. 최초 상태의 후보쌍은 **80×1043=83,440개**다. 먼저 전체 1대1 교체 가능성을 조사하면32×32 shortlist에 따른 거짓 음성 판단을 줄일 수 있다.

전체 Patch 거리 행렬은 만들지 않는다. CLS 거리 행렬과 최근접·차근접 거리를 활용해 후보를 나누어 검사할 수 있다. 다만 구현의 정확성·실측 시간은 아직 확인하지 않았다.

기록할 값은 검사한 쌍 수, 허용쌍 수, 서로 다른 유입/유출 이미지 수, 반경 변화, 계산 시간이다. 일부만 검사하고 상한에 도달하면 **미완료**로 보고한다.

- 허용 교체가0이면 이 초기 집합의 **1대1 교체 경로로는 시작할 수 없다.** Patch 추출은 보류한다.
- 허용 교체가 있어도 연속 교체 후 계속 가능하다는 보장은 없다. 다음 상태에서 제약을 다시 검사해야 한다.
- 0이라는 결과가 여러 장을 동시에 바꾸는 모든 방법의 불가능성을 증명하지는 않는다. 이번에는 다중 교체 탐색이나 ε 완화를 자동 추가하지 않는다.

### 2단계: 통과한 경우에만 고정 Patch 표현으로 선택 진단

최신 Patch cache 유무를 확인한다. CLS만 저장돼 있으면 Patch를 복원할 수 없으므로 **이 단계는 별도의 GPU 추출 승인이 필요하다.** 이번 문서는 그 승인이나 추출 실행을 포함하지 않는다.

표현은 기존 제안 하나로 고정한다: 같은 ViT-S/14·F518·마지막 층, padding 면적 처리, 이미지별4×4 지역 descriptor(최대16개), train-only prototype256개. 모델·해상도·층·prototype 수를 성능에 맞춰 탐색하지 않는다. 먼저 작은 고정 표본에서 기존 CLS 재현·token1369개·좌표·메모리를 점검한다. 이 표현이 결함을 표현한다는 가정은 하지 않는다.

지역 목적함수는 기존 제안 `F_P(T)=mean_j max_{x∈T} a_xj`를 유지한다. 최초 `F_P(T₀)`와 전체 train의 `F_P(V)`를 함께 기록해 개선 가능한 여지를 확인한다. 차이가 계산 정밀도 수준이라면 **목적함수 포화**로 보고하며, Patch가 무용하다고 단정하지 않는다.

Patch 이득이 양수이고 CLS 반경을 통과하는 교체만 수락한다. 기존32×32 shortlist는 계산 절약용으로 쓸 수 있으나 탐색 범위를 기록하고, 후보가 없으면 현재 상태의 전체 1대1 검사를 통해 shortlist 한계인지 구분한다. 시간 상한 때문에 전체 검사를 못 하면 탐색 미완료다.

기존10 pass 대신 **수락 교체 최대80회**를 사전 상한으로 제안한다. 같은 이미지를 다시 바꾸더라도 최종 변화는 최초 B와의 차이로 센다. 구현·검토 시 기록할 계산 상한은 `CPU 시간 ___분`이며, 예를 들어30분을 제안값으로 정할 수 있지만 예상 실행시간이라는 뜻은 아니다. 상한을 넘으면 중단하고 원인을 보고한다.

### 2-a단계: R4 24장으로 Patch 신호의 결함 관련성 최소 점검

1. FF 재현·초기 교체 가능성 검사 통과 후, **GT를 열기 전에** R4 ID-hash 순서24장, 상위지역 최대3개, 무작위 지역 대조200회, 코드·입력 hash를 고정한다. 클래스나 좋은 예시에 맞춰 표본을 바꾸지 않는다.
2. 실제 선택에 쓰려는4×4 지역 descriptor와 train-only prototype을 사용한다. cache가 없으면 별도 추출·구성 결정이 필요하며 자동 실행하지 않는다. 원래 모든 token의 효과를 검증한 것으로 확대 해석하지 않는다.
3. 각 표본 x를 R4 전체에서 제외한480장을 참조해 `F(R4)−F(R4\{x})`의 지역별 기여를 계산한다. prototype별 양의 기여를 가장 유사한 지역에 배분한다. 자기 자신 때문에 생기는 포화를 피하되, 같은 패턴이 다른 이미지에 충분히 있으면 진짜 포화일 수 있다. 기여≤1e-9면 임의 강조 위치를 만들지 않는다.
4. 점수와 강조 지역을 봉인한 **이후**, 별도 사후 명령만 고정24장의 정답 box를 읽는다. 미라벨 GT나 다른 ID가 입력에 포함되면 중단한다. 원본 영상의 normalized xyxy 좌표를 사용하고, 강조 지역 면적 중 box 합집합 비율을 계산한다. 중복 box는 한 번만 센다.
5. 같은 이미지에서 같은 수의 유효 지역을 무작위로 고른200회 대조와 비교한다. 이 대조는 공간 겹침의 우연 수준을 점검하는 것이며, 선택 이미지의 임의 교체3개와 다르다. 평균·5/95분위는 기술통계이고 AP 신뢰구간이나 유의성 판정이 아니다.
6. 이미지·기여 지역·R4 box가 표시된 HTML과 기록표로 형태/배경·조명/padding/중복/불명확을 함께 기록한다. 포화와 box 없음도 별도 분모로 보고한다. 24장이나 특정 겹침률을 성공 기준으로 쓰지 않는다.

이는 이미 라벨된 R4를 사용하는 **탐색적 표현 진단**이다. GT를 선택 점수·prototype·영역 추출에 사용하지 않는다. R4는 이미 FF로 선택된 집합이고 box 안에도 배경이 포함되므로 독립 검증·정확한 결함 인식·전체 pool 일반화로 해석하지 않는다. 이 진단을 보고 표현을 바꾸면 새 버전이며 같은24장에 대한 반복 튜닝 결과를 독립 증거로 보고하지 않는다.

현재 제공 코드는 기존 cache의 읽기·기여 계산·사후 평가·시각화까지다. DINO 추출기, prototype fitting, Patch/임의 교체 획득 알고리즘은 포함하지 않는다. 이 입력들이 없으면 준비 단계에서 멈춘다.

### 3단계: 값이 오른 것과 의미 있는 변화를 구분

비교 대상은 **원래 FF / Patch를 쓴 허용 교체 / Patch를 쓰지 않는 임의의 허용 교체** 세 가지다. 마지막 것은 새 연구 후보가 아니라 단순 치환만으로 얻는 변화를 확인하는 진단 대조군이다. 고정seed3개와 같은 교체 횟수·반경 제약으로 계획하며 YOLO는 학습하지 않는다. 임의 대조가 같은 교체 수에 도달하지 못하면 그 차이를 공개하고 동등 조건 비교로 해석하지 않는다.

목적함수 이득은 기전 지표로 쓰고, 독립적인 유용성 입증으로 쓰지 않는다. 최종 유입/유출 집합을 CLS 거리로 결정적으로 대응시켜 실제 영상을 비교한다. 최대20쌍을 ID-hash로 선정하고 적으면 전부 본다. 가능하면 어느 쪽이 새 선택인지 가린 상태에서 다음만 기록한다.

- 국소 형태·질감 차이가 보이는가?
- 주된 차이가 배경·조명·해상도·padding·노이즈인가?
- 사실상 같은 영상/기존 중복 그룹의 치환인가?
- 판단할 수 없는가?

실제 교체 쌍 검토는 봉인된 최종 순유입/순유출을 CLS로 결정적으로 대응시킨다. 기여 지도는 양쪽에 공통인 `원래 R5−대응 유출 이미지`를 참조해 계산하므로 순차 선택 당시의 인과적 이유나 step trace와 같다고 주장하지 않는다. 방법·A/B 유입 여부를 가린 화면과 별도 키를 사용하고, 대조군이 같은 수락 교체 횟수에 도달하지 못하면 비교 한계를 명시한다.

이는 봉인 후의 정성 점검이며 GT class/bbox를 선택에 주지 않는다. 사람이 결함처럼 보인다고 판단한 것을 정답 검증으로 취급하지 않는다. 결과를 보고 규칙을 고치면 새 탐색 버전으로 구분하고 이번 진단과 합치지 않는다.

## 5. ‘의미 있게 달라졌다’의 판정 기준

최종 신규집합을 B′라 두고 **순교체 수 `r=|B′\B|`**, 신규분 교체율 `r/80`, 전체 라벨 집합 변화율 `r/561`을 따로 보고한다. Jaccard나 overlap을 함께 쓰더라도 분모를 명시한다. 교체 연산 횟수를 순교체 수로 세지 않는다.

초기 작업 기준으로 **신규80장 중10% 이상, 즉 순교체8장 이상**을 제안한다. 이는 후속 탐색을 계속할지 판단하는 실무 참고값이며 연구 성과·성공/실패를 나누는 학술적 문턱이 아니다. 전체561장으로는 약1.43%이므로 큰 데이터 변경처럼 표현하지 않는다. 실행 전에 채택 여부를 정하고 결과를 본 뒤 낮추지 않는다.

다음 항목을 **함께** 확인한다.

| 판단 항목 | 함께 검토할 내용 |
|---|---|
| 기준의 유효성 | 원래 FF R5·거리 정의·동일 예산이 재현됨 |
| 반경 유지 | 동일 V와 float 규칙에서 `ρ(T′)≤ρ(T₀)`; ε는0 |
| 분포의 부작용 | 평균·95분위 거리와 중복성을 함께 보고. 반경만 유지하고 다른 지표가 악화되면 대표성 유지 주장을 제한 |
| 실질적인 변화량 | 순교체8장 기준은 탐색 지속 여부의 참고값으로만 사용. 동일 중복 그룹 치환을 제외한 변화 수도 별도 보고 |
| Patch의 역할 | 임의 허용 교체보다 어떤 지역 시각 차이가 생겼는지 설명 가능. 목적함수 상승만 제시하지 않음 |
| 영상 근거 | 좋은 예시뿐 아니라 배경 변화·중복·불명확 사례를 같은 방식으로 공개 |

8장 이상 바뀌어도 배경만 달라지면 다음 탐지 실험으로 넘어갈 근거는 약하다. 5장만 바뀌어도 명확히 다른 결함 형태가 관찰되면 흥미로운 후속 검토 근거가 될 수 있다. 8장 미만이라는 이유만으로 실패로 분류하거나 중단하지 않으며, 모든 Patch 활용이 무용하다고 일반화하지 않는다. 이 경우 기준을 사후 수정하는 대신 변화량과 정성 관찰을 별도로 보고한다. 의미가 불명확하면 ‘판정 유보’를 허용한다.

## 6. 결과별 다음 결정과 이번 추천

| 예상 가능한 결과 | 다음 결정 |
|---|---|
| 원래 FF가 재현되지 않음 | cache·전처리·선택 코드 연결부터 해결. Patch/GPU 보류 |
| 최초의 허용 1대1 교체가 없음 | 엄격한 반경 아래 이 교체 방식은 보류. ε 완화·다중 교체는 별도 설계 여부 판단 |
| 허용 교체는 있으나 Patch 목적이 포화됨 | local 집계 방식의 한계로 기록. 자동 파라미터 탐색 금지 |
| local 이득·ID 변경이 있으나 중복/배경 변화 위주 | 결함 관련성 근거 부족. YOLO 학습 보류 |
| 반경 유지·중복 아닌 변화·설명 가능한 국소 차이가 관찰됨 | 다른 고정seed에서도 관찰되는지 작은 반복을 별도 검토. 아직 AP 개선·신규성은 주장하지 않음 |
| 시간 상한으로 탐색을 마치지 못함 | 불가능/실패가 아니라 계산 범위 내 미완료로 보고 |

**최종 추천은 ‘CLS만으로 교체 가능성을 확인하는 제한된 CPU 진단’부터 검토하는 것이다.** 이 단계가 통과하면 Patch 진단의 비용과 의미가 생긴다. 당장 YOLO를 학습하거나 새 방법을 확정할 이유는 없다. 가능성이 보이면 본 문서의 R4 최소 사후 진단을 검토하고, 독립적인 결함 관련성 검증·반복 범위·탐지 실험은 다음 의사결정으로 남긴다.

다음 실행을 결정할 때 정할 것: `GC10 / seed2026091901 / R4→R5 / ε=0 / CPU 상한 / Patch 추출 별도 여부 / 순교체8장 기준 / 중단 조건`. 현재 승인 범위는 집에서 사용할 FF·Patch 최소 진단 코드 준비·합성 입력 검증·같은 GitHub 브랜치 전달이다. 실제 원본 진단, Patch 추출, YOLO 학습 실행을 승인한 것으로 간주하지 않는다.
